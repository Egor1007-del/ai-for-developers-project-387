Этот навык создаёт спецификацию на основе текущего обсуждения и знания кодовой базы. Не проводите интервью: обобщите уже известную информацию.

Используйте предоставленные сведения о трекере задач и метках triage. Если их нет, попросите пользователя запустить `/setup-matt-pocock-skills`.

## Порядок работы

1. Изучите репозиторий, чтобы понять текущее состояние кодовой базы, если ещё этого не сделали. Используйте во всей спецификации терминологию глоссария проекта и учитывайте относящиеся к задаче ADR.

2. Наметьте точки взаимодействия, через которые будет тестироваться функциональность. Предпочитайте существующие точки новым и выбирайте максимально высокий уровень. Если нужны новые точки, предложите их на максимально высоком уровне. Чем меньше таких точек в кодовой базе, тем лучше; в идеале — одна.

Уточните у пользователя, соответствуют ли эти точки его ожиданиям.

3. Напишите спецификацию на русском языке, используя заголовки шаблона ниже, и опубликуйте её в трекере задач проекта. Добавьте метку `ready-for-agent`; дополнительный triage не требуется.

## Постановка проблемы

Проблема, с которой сталкивается пользователь, с его точки зрения.

## Решение

Решение проблемы с точки зрения пользователя.

## Пользовательские истории

Подробный нумерованный список пользовательских историй. Формат каждой истории:

1. Как <роль>, я хочу <возможность>, чтобы <польза>.

<user-story-example>
1. Как клиент мобильного банка, я хочу видеть баланс своих счетов, чтобы принимать более обоснованные решения о расходах.
</user-story-example>

Список историй должен быть максимально подробным и охватывать все аспекты функциональности.

## Решения по реализации

Список принятых решений по реализации, включая при необходимости:

- Модули, которые будут созданы или изменены
- Интерфейсы этих модулей, которые будут изменены
- Технические уточнения разработчика
- Архитектурные решения
- Изменения схемы данных
- Контракты API
- Конкретные взаимодействия

Не указывайте конкретные пути к файлам и фрагменты кода: они могут быстро устареть.

Исключение: если прототип содержит фрагмент, который точнее текста выражает принятое решение (автомат состояний, reducer, схему или структуру типа), включите его в соответствующий пункт и кратко отметьте, что он взят из прототипа. Оставьте только важные для решения части, а не работающую демонстрацию целиком.

- Какие модули будут тестироваться
- Примеры для тестов: похожие виды тестов в кодовой базе
